# GeekSuite GraphQL

A map of the suite's single GraphQL surface: where it runs, how it is assembled,
and what every app exposes through it. Written 2026-09-12 from the typeDefs
themselves; when this file and `apps/basegeek/packages/api/src/graphql/<app>/typeDefs.js`
disagree, the typeDefs win. §4's field tables are generated by
`tools/gql-surface.mjs` (2026-11-06) — run it with `--write` instead of editing them.

## 1. Where it lives

- **One Apollo Server**, mounted at `/graphql` in basegeek
  (`apps/basegeek/packages/api/src/server.js`, `new ApolloServer({ typeDefs, resolvers })`
  then `expressMiddleware`). Host port **8987**.
- **Every suite app's nginx** proxies its own `/graphql` location to
  `http://192.168.1.17:8987/graphql` (see `DOCS/RUNBOOK.md` §2 and the nginx section), so the
  browser talks to whichever app domain it is on and lands here. Startgeek is the exception:
  it calls basegeek's public URL directly via `apps/startgeek/src/lib/graphql.js`.
- **Auth**: `optionalUser({ validateSession: localSessionValidator })` — the JWT is verified
  in-process with basegeek's own secret and the user loaded from Mongo (no HTTP round-trip to
  itself; see `DOCS/CONTEXT.md` and BURN_REVIEW_2 §3). The resolver context is
  `{ user: req.user || null }`; resolvers enforce ownership themselves.
- **Logging**: every POST with an `operationName` is logged as
  `[GQL] <operationName> | vars: [<variable names>]` — names only, never values.
- **Operations**: `Query` and `Mutation` only. There is no `Subscription` type.

## 2. How the schema is assembled

`apps/basegeek/packages/api/src/graphql/index.js` merges (via `@graphql-tools/merge`):

```
shared/typeDefs.js          scalars + cross-app types
basegeek/typeDefs.js        admin, API keys, aiGeek
notegeek/typeDefs.js        (declares the root `type Query` / `type Mutation`)
todogeek/typeDefs.js
flockgeek/typeDefs.js
fitnessgeek/typeDefs.js
bookgeek/typeDefs.js
gamegeek/typeDefs.js
thinggeek/typeDefs.js
thinggeek/attic/typeDefs.js household-papers vault inside ThingGeek
newsgeek/typeDefs.js
glance/typeDefs.js          StartGeek front page (read-only)
suitetags/typeDefs.js       cross-app tags (notegeek/todogeek/thinggeek)
```

`graphql/catalog/` has **no** typeDefs — it is shared search/indexing machinery
(`catalogSemantic`, `catalogText`, `salvagePicks`) imported by notegeek's semantic
search and bookgeek/gamegeek's `whatNext`, not a schema module.

Each app module owns `typeDefs.js`, `resolvers.js`, usually `validation.js` (zod), and its
Mongoose `models/`. Scalar resolvers for `Date` and `JSON` live in `index.js`.

Do **not** import services (e.g. `services/aiFeatureRunner.js`) from a typeDefs file:
`tools/gql-arg-audit.mjs` imports every module's typeDefs standalone with no env.

## 3. Shared types (`shared/typeDefs.js`)

| Type | Purpose |
|---|---|
| `scalar Date` | ISO-8601 date/datetime. Parses strings and integer millis; serializes to `toISOString()`. |
| `scalar JSON` | Pass-through. Object literals must be sent as variables, not inline. |
| `AIProvenance` | `source!`, `reason`, `model`, `provider`, `cached!`, `callsToday!`, `cap` — attached to every AI-assisted result. `source: "fallback"` means no model was consulted. |
| `DeleteResponse` | `success!`, `message` |
| `SaveOrderResponse` | `success!`, `updatedAt` |
| `TagCount` | `tag!`, `count!` |

## 4. Per-app surface

The field tables in this section are **generated**. `node tools/gql-surface.mjs --write`
rewrites the block between the markers (or `pnpm gql:surface` prints the same list to
stdout), and the `gql-audit` CI job fails the build if the committed block drifts from
the typeDefs. Only the module notes under the block are hand-maintained — put a field's
*meaning* there, never its signature.

### Module notes (hand-maintained)

- **basegeek** — `aiFreeModels` and `aiRecommendModel` are authenticated, **not**
  admin; `AIRecommendedModel.score` (0–100) is only a tiebreaker — `reasoning` is the
  answer. `saveAIConfig` treats a blank key as "keep"; `removeAIProviderKey` is the only
  way to delete a stored credential. `setCatalogOverride` takes `'deny' | 'allow' | null`
  (anything else clears). Retired mutations kept as comments in the typeDefs for
  archaeology: `bulkUpdateFreeTiers`, `updateModelPricing`, `updateModelFreeTier`,
  `resetAllFreeTiers`, `seedDirectorPricing`, `seedDirectorFreeTier`, `testAIProvider`,
  `syncProviderModels` — the catalog job observes what these used to assert.
- **notegeek** — `noteVersions` returns newest-first with `content` null by design;
  `noteVersion(id)` fetches one body. `updateNote.changeReason` labels the history entry
  (`edit` default, `compose`, `restore`); `restoreNoteVersion` snapshots the current
  state first, so a restore is undoable. `composeNote` builds a NEW document from a pile
  of scraps and writes nothing; `ComposeStats.{chunksFailed, truncated, degenerate}` are
  the caller's to report. `tidyMarkdown` was removed 2026-09-22 — Compose replaced it.
  Content is sanitized on save through `notegeek/sanitize.js` (same DOMPurify profile as
  the client). `notes` `under` walks the nested-tag subtree (`house` → `house`,
  `house/garage`, never `houseboat`); `searchNotes(hybrid: true)` fuses keyword with
  LOCAL embeddings and reports `matchedBy` + `why`. `foldInPreview`/`foldInApply`
  merge pasted content into an existing note behind a client-confirmed proposal;
  `transcribeSketch` turns a handwriting image into text; `archiveNotes`/`restoreNotes`
  are the soft-delete pair `archivedNotes` reads.
- **todogeek** — `dailyTasks`/`weeklyTasks`/`monthlyTasks` expand recurring series per
  window and exclude blocked tasks; `blockedTasks` is the only list where they surface.
  Recurrence is an RRULE string (`DTSTART:...\nRRULE:FREQ=WEEKLY`); `recurrencePattern`
  is deprecated and translated server-side. `blockTask` is BAD_USER_INPUT on
  completed/cancelled and materializes a blocked override on a virtual occurrence.
  `reorderSubtasks` must name every child exactly once. `deleteCollection` detaches
  entries unless `deleteTasks`. `deleteHabit` takes its log history with it.
  `toggleHabitLog` is idempotent per calendar day. `pushVapidKey` null = reminders not
  configured on this deployment. `reviewDraft` wants a Monday `weekStart`, is opt-in via
  `appPreferences.todogeek.aiReviewDraft`, capped at 10 model calls/user/day, and
  degrades to deterministic with `provenance.reason: "opted_out"` —
  `createJournalEntry.aiDrafted` is where a saved draft gets stamped.
- **flockgeek** — `deleteFlockEntity` is one generic delete for every entity type.
- **fitnessgeek** — the largest module; several reports/insights return `FitnessJSON`
  rather than a shaped type. `bodyCompositions` returns scans oldest-first over an
  inclusive UTC calendar-day window; `derived` is recomputed on read by
  `@geeksuite/schemas`' `derive()`, never stored. `bodyCompositionSummary.current` is a
  14-day mean, `change` is 7-day mean vs 7-day mean with centres ≥ 14 days apart, `bmr`
  is Katch-McArdle while the latest scan is ≤ 30 days old else Mifflin. `addFitnessWeight`
  keeps ONE weight per UTC calendar day (upsert, `source: 'manual'`). `derivedMacros`,
  `activeNutritionGoals`, report `goalCompliance` and the AI context all derive through
  `@geeksuite/utils` `deriveMacroTargets`/`macroRules`/`macrosForCalories` — protein per
  lb of lean mass while a scan ≤ 30 days old; keto plans get keto macros.
  `parseFoodEntry` (≤ 500 chars) is read-only — it proposes, never logs; only the hour
  of `date` is read to pick a meal type. `FitnessUserSettings` is shared with the REST
  settings routes through one module — add fields there first
  (`apps/fitnessgeek/DOCS/USER_SETTINGS_SCHEMA.md`).
- **bookgeek** — per-reader state (shelf, rating, review, progress, `myTags`) lives in
  `bookreadings` and is overlaid at read time — never written onto `Book`; see
  `apps/bookgeek/DOCS/PER_READER_SHELVES_PLAN.md`. `whatNext` and `draftBookMetadata`
  are AI-backed with provenance.
- **gamegeek** — `gameWhatNext`/`gamesLike` read shelves and ratings by the taste model
  in `apps/gamegeek/DOCS/TASTE_MODEL.md`, not by their generic meanings (a 2★ is
  "compulsive but unsatisfying", not simple dislike). `setGameState` writes shelf +
  rating + play state; `logGameSession`/`saveGamePlaythrough` carry the history.
- **thinggeek** — `thingAttention` is the "what's expiring or due" feed; `thingTree` is
  the containment tree ("what's attached to X"); `thingInsuranceTotals` feeds the
  insurance report. Deletes go to trash — `trashedThings`/`restoreThing`. The household
  member gate is enforced in every resolver AND in the app backend.
- **thinggeek/attic** — the household-papers vault inside ThingGeek: persons, document
  types, documents; every read is journaled to `atticAccessLog` (default limit 40).
- **newsgeek** — sources are managed per-source and per-publisher
  (`newsSetPublisherPref`, `newsSetPublisherOpener`); `newsFrontPage` is the assembled
  front page; `newsCheckSourceNow` forces a fetch outside the schedule.
- **glance** — read-only, built for StartGeek's front page. `glanceToday` is one
  round-trip for tasks/habits/recent notes/reading/fitness/flock. `glanceAsk` is an
  AI-planned search over the caller's own Things: `intent` echoed back as chips,
  `answer` null unless grounded in context, `citations` are result ids. `glanceDraft`
  drafts only — `degraded: true` + a null draft means carry on as if AI were off.
  `calendarEvents` reads ICS feeds by URL.
- **suitetags** — the cross-app tag spine: `suiteTags` aggregates the caller's tags
  across notegeek, todogeek and thinggeek with per-app counts; `taggedAcross` returns
  items carrying the tag (or its `under` subtree) across those apps, ≤ 50 per app,
  newest first.
## 5. Guards and tooling

- **Argument drift audit** — `tools/gql-arg-audit.mjs` (`pnpm check:gql`, CI job `gql-audit`)
  catches resolvers reading args the schema doesn't declare, and vice versa. GraphQL itself
  will not report this. See `DOCS/RUNBOOK.md` "GraphQL argument audit".
- **Schema loads** — `apps/basegeek/packages/api/src/__tests__/gatewaySchemaLoads.test.js`
  fails the build if the merged schema doesn't parse (an unescaped backtick inside a `gql`
  template literal has bitten before; see RUNBOOK).
- **Parity tests** — `fitnessgeekSchemaParity.test.js` and `userSettingsSchemaParity.test.js`
  keep the gateway's fitnessgeek types in step with the shared model modules.
- **CSRF** — every frontend's GraphQL client appends `csrfHeaders()` last; see `DOCS/CONTEXT.md`
  for the double-submit token and the shared `geeksuite:csrf-reload-attempted` guard.
- **Errors** — a 401 or a real `UNAUTHENTICATED` GraphQL error logs the user out; 5xx does not.

## 6. Adding to the schema

1. Edit `apps/basegeek/packages/api/src/graphql/<app>/typeDefs.js` and `resolvers.js`; add zod
   rules to the module's `validation.js`.
2. Cross-app shapes (provenance, delete responses, tag counts) go in `shared/typeDefs.js`
   once — never redeclare them per module.
3. Run `pnpm check:gql` and the gateway tests.
4. Run `node tools/gql-surface.mjs --write` so §4's tables track the typeDefs — CI
   (`gql-audit`) fails on a stale block. Only the module notes are edited by hand.
5. Update the matching client `graphql/` folder
   (`apps/<app>/frontend/src/graphql/` or `apps/bookgeek/web/src/graphql/`).
