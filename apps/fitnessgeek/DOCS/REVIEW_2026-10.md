# FitnessGeek — Review, 2026-10-16

*Chef: "I'm getting a bunch of complaints of 'this or that doesn't work'. I think some of it is
that it isn't as intuitive as it could be… This app is now getting real use by my wife, a
non-technical audience."*

**Status: review only. Nothing here is fixed yet.** The plan in §5 is waiting on Chef's
decisions in §6.

How this was done:
- A read-only code review in three parts, run in parallel: the food-logging path, everything
  else, and a UX walkthrough as Heather using the harness screenshots.
- Two days of production logs.
- Spot-checks of the headline findings against the code before they went in here.

A tag on each finding says how sure it is:
- **verified**: re-read in the code for this document.
- **traced**: the reviewing agent followed the code end to end.
- **plausible**: the code allows it, but it depends on the phone or on data.

---

## 1. The short version

"Doesn't work" is mostly five things. None of them is a crash.

1. **The food box tells her to do the wrong thing.**
   - She types a sentence. The screen shows a list of near-misses and, when nothing matches,
     **"Nothing found — Try fewer words, or create it below."**
   - The real action, "Log '…'", is styled like the first search result.
   - Any row she taps logs at once, with no visible "+".
   - Chef's suspicion is right: the AI path works, and the screen hides it.
2. **The app forgets what day it is.** An installed PWA kept alive overnight is still on
   yesterday in the morning:
   - Food Log adds go to yesterday.
   - The first med tick writes yesterday's dose, then vanishes.
   - The quick weight overwrites yesterday's weight.
3. **She gets signed out.**
   - The shared Apollo client logs out on any GraphQL 401 and never tries a token refresh.
     Tokens last 1 hour, so this hits every app in the suite, not just this one.
   - A 502 during a fleet restart also lands her on the Login splash.
4. **Errors are either raw or missing.**
   - Raw: "Request failed with status code 502", "Network Error", and MongoDB E11000 text with
     her user id in it.
   - Missing: undo, med saves and settings fail silently.
   - The offline banner promises a sync that does not exist.
5. **Taps are slow and unguarded.** Logging a food waits for the whole page to reload before
   showing anything, which takes 1–3 s on a phone. Nothing is disabled meanwhile, so a second
   tap logs it twice.

Also likely: **Heather has drifted out of Simple mode.** Her mode was never saved. The default
rule switches to Full as soon as she has logged anything. So the app she sees now is probably
not the one designed for her.

## 2. What production shows (2026-10-14 → 16, the 44 h since the last container recreate)

- **Heather's searches, 2026-10-15.** She types word by word, and every pause fires the deep
  search, AI included:
  - `Qu`, `Ques`: abandoned.
  - `Fried`, `Fried brea`, `Fried breadd`, `Fried bread`, `Fried breaded`,
    `Fried breaded chicken`, `Fried breaded chicken breast`: 25 results, no describe.
  - `Ho`, `Homemade`, `Homemade French`, `…fries`, then **describe-and-log** (it worked).
  - `Grilled`, `Grilled chicken`: no describe. `Ranch dressing`, then describe.
  - Whether the non-describe searches ended in a tapped row or in giving up is not in these
    logs (see §7).
- **Deep search runs on 2-letter prefixes, with AI as a source.** One "Food search" record
  shows `query: "Ha"` with sources including `ai`, top hit "Ha"; `Hal` came back with
  "hal PICKLED BABY BEETROOT THE". That is the "pretty useless" list, and it costs model calls.
- **CalorieNinjas is dead.** Every call answers `400 Invalid API Key.`
  (`CALORIENINJAS_API_KEY`). 8 failures.
- **OpenFoodFacts is down on their side.** 73 × 503 and 14 × "Breaker is open" in 44 h.
  The breaker is doing its job, but every search pays for the attempt until it trips.
- **Redis caching is disabled in production.** The startup line reads `Redis caching: disabled`
  (`backend/src/server.js:42`), so the 7-day USDA/OFF cache the search plan relies on is not
  caching. Deep searches took 300–1,800 ms each in the logs. Worth knowing why before tuning
  anything else.
- **401s:** 6 on fitnessgeek and 12 on basegeek in 44 h. That fits item 3 in §1.

### P2 — edge cases, latent, or Chef-only

- **Food path:**
  - Save Meal previews "0 cal": it reads `food_item.nutrition`, which the query doesn't select (`SaveMealDialog.jsx:73`).
  - Saved meals never appear in suggest, and My Meals has no "log this" (`unifiedFoodService.suggest`).
  - Stale deep results land after the box is cleared, because the request isn't aborted (`UnifiedFoodSearch.jsx:198`).
  - Separated-fragment searches drop `userId`, so her own foods vanish for "a and b" queries (`unifiedFoodService.js:315`).
  - The background judge rescales calories she already corrected through the portion question (`describeAndLogService.js:383`).
  - "Updated to X cal" shows even when the write failed (`UnifiedFoodSearch.jsx:446`).
  - A describe that times out on the client still writes on the server, so a retry duplicates it.
  - Every tapped AI result creates a new **global** food that Chef sees in search (`unifiedFoodService.js:538`).
  - Quick picks keep offering soft-deleted foods.
  - The session ribbon counts saved meals as 0 cal.
  - The recent-logs cache stores a failed fetch as empty for 2 minutes, so the chips vanish after a deploy blip.
  - The Android back gesture probably leaves the page instead of closing the sheet (plausible).
- **Ownership, latent:**
  - `GET /api/foods` with no search returns every user's custom foods. The caller is unused today.
  - The REST barcode lookup is unscoped.
  - Gateway `deleteFitnessMedication` leaves dose logs behind.
- **Everything else:**
  - No React ErrorBoundary anywhere, so a bad data shape gives a white screen.
  - Reports blocks on two AI calls before showing anything, and shows raw GraphQL errors.
  - CSV and AI reports use a UTC window, which shifts a day after 19:00 Central.
  - The Home streak card reads the envelope and shows 0 (likely; Full only).
  - The Home and BP pages can show the morning reading as "current" (sorted by `log_date` only).
  - Settings saves the whole loaded snapshot, so a failed load followed by Save writes defaults and turns Garmin off.
  - A failed first-run save gives no feedback.
  - A failed meds load reads "No medications yet".
  - Simple Home has no way in to add a first medication.
  - `fg.experience.v1` and the streak key aren't per user, and the dead account's cache can paint first.
  - An evening plan stores tomorrow as its start date.
  - The weight chart is empty once the goal date has passed.
  - Weight and BP "Deleted successfully" shows even on a `false` result.
  - Number inputs lack `inputMode="decimal"`, so some Samsung keyboards can't type 150.4.
  - The first-run goal ("lose a little") is stored and never used: Home says "No daily target is set".
  - Uploads use raw `fetch` with no refresh on 401.
  - The scale-import folder→user cache can follow a dead id until a restart.
  - The household may still list the dead account (689931bb…) if its settings row kept the id (plausible).
  - `share_meals` is stored but nothing reads it.

## 4. UX — walking it as Heather

Task: type "a bowl of chicken soup and some crackers" into **Add to lunch**.

1. **Typing:**
   - A one-line box with a magnifying glass. A long sentence scrolls sideways out of sight.
   - Her own foods appear at 150 ms, then the deep and AI results at 400 ms, re-sorting under
     her finger.
   - It may say "No single match… showing its parts instead".
2. **The real action** is a pale tinted row, "Log '…'", with a 12 px subtitle. It reads as
   result #1. Enter also triggers it, and nothing says so.
3. **No match:** "Nothing found — Try fewer words, or create it below", plus
   "Create '<her whole sentence>'". This is the most misleading string in the app: it tells her
   to shorten a sentence the app would have handled.
4. **Any row logs on tap.** The "+" icon is `display:none`, and the calorie number has no unit.
   "Pick the closest" quietly logs a grilled chicken breast.
5. **Thinking:** "Logging…" at 70% opacity, no spinner, and everything else still tappable.
6. **Result:** the sheet closes, and a **4-second** toast is the only place to see what was
   guessed or to undo it.
7. **Fixing a wrong guess:** find the row on Log, then Edit. Edit offers servings, meal and
   notes, but not calories. "1.5 servings of a bowl of chicken soup" isn't a question she can
   answer.

Other friction, in order of harm:
- **Wrong day is silent.** The add sheet never says which day. "Same as yesterday's" is
  relative to the date on screen. "Last night" in the text isn't parsed.
- **Voice logs as soon as she stops talking.** The only sign of what it heard is the 4 s toast.
- **Simple Home's** first screen is the ring plus a sentence repeating the same number, so no
  Add button is visible without scrolling (worse with Larger text).
- **The Today strip's "Weighed —"** reads as a status, not a button. It leads to Weight, where
  the only way to log is an unlabelled "+".
- **Simple Log still shows** the calorie gear (it can change her goal), "Includes 240 extra for
  today's activity", and a FAB over the Again chips.
- **BP fields say** "Systolic / Diastolic". Save is top-right, away from the thumb.
- **Small targets:** 12 px portion buttons, and star / pencil / trash side by side on every log
  row.
- **The harness has no picture of the add box while typing, thinking, after a result or after
  an error.** The surface she complains about is unaudited. The `09-20` PNGs in
  `out/ci/fitnessgeek/` are stale orphans in the old teal look.

Keep:
- Plain sentences and full dates.
- The four produce meal cards, each with its own Add.
- "Same as yesterday's lunch" and the Again chips.
- "Did you take your meds?" ticks.
- The three-step first run. Its "Say it or type it — 'two eggs and toast' is enough" is the
  right line in the wrong place.
- Toasts that name the meal.
- The portion question after logging.
- Larger text, the Home · Log · Weight · More nav, and Market Morning.

### The food box, redesigned: "just tell it"

One composer. **The sentence is the default; the list is something you ask for.**

On a phone it's the same bottom sheet:
- A multi-line box, 2 lines at rest and up to 5.
- A full-width **Log it** button directly under it, so it stays above the keyboard.
- A big mic beside it, not a glyph inside the box.
- Enter means send (`enterKeyHint="send"`), and the key says so.
- Barcode becomes a text link.

```
EMPTY                                   TYPING A SENTENCE
┌──────────────────────────────────┐    ┌──────────────────────────────────┐
│ ✕  Add to lunch · Today          │    │ ✕  Add to lunch · Today          │
│ Tell me what you ate             │    │ ┌──────────────────────────────┐ │
│ ┌──────────────────────────────┐ │    │ │a bowl of chicken soup and    │ │
│ │e.g. a bowl of chicken soup   │ │    │ │some crackers                 │ │
│ │and some crackers             │ │    │ └──────────────────────────────┘ │
│ └──────────────────────────────┘ │    │ ┌─────────────────────┐ ┌──────┐ │
│ ┌─────────────────────┐ ┌──────┐ │    │ │   ✓  Log it         │ │  🎤  │ │
│ │   ✓  Log it  (dim)  │ │  🎤  │ │    │ └─────────────────────┘ └──────┘ │
│ └─────────────────────┘ └──────┘ │    │ I'll work out the calories. You  │
│ Say it like you'd tell a friend. │    │ can fix anything after.          │
│ ── Or tap one you've had ──      │    │ ▸ Or pick an exact food (12)     │
│ [Same as yesterday's lunch    ]  │    └──────────────────────────────────┘
│ (Chicken Caesar)(Sourdough)…     │
│ Scan a barcode                   │    RESULT
└──────────────────────────────────┘    ┌──────────────────────────────────┐
                                        │ ✓ Added to lunch                 │
THINKING                                │ Chicken soup, 1 bowl  220  [Fix] │
┌──────────────────────────────────┐    │ Crackers, ~6          130  [Fix] │
│ "a bowl of chicken soup…" (r/o)  │    │ [ Undo all ]        [ Done ✓ ]   │
│ ◌  Working it out…               │    └──────────────────────────────────┘
│ (chips and list disabled)        │
└──────────────────────────────────┘
```

- **Sentence detection is cheap and client-side:** 3+ words, a number, "and", "with" or a
  comma. In sentence mode:
  - the list folds into "Or pick an exact food (n)";
  - "Nothing found" never appears;
  - the deep and AI search is skipped, which also stops the per-keystroke model calls in §2.
- **Short queries** ("fage") show the list open, with a visible **+ Add** pill and "190 cal" on
  each row.
- **Thinking:** the box goes read-only, a spinner says "Working it out…", and everything else is
  disabled. After 8 s it says "Still working — this one's taking a moment."
- **Errors, in plain words, with her text kept:**
  - Offline: "No signal — I can't log this yet. Your words are saved here."
  - Failure: "That didn't go through. Tap Log it to try again."
  - Nothing understood: "I couldn't find a food in that. Try naming the food."
  - Partial: "Logged the soup. I couldn't work out 'crackers'. [Pick crackers]"
- **Fix** opens one small sheet:
  - About right / Smaller / Bigger;
  - an editable calorie number;
  - "It was actually…", which re-describes just that item.
- **Voice:** the result says "I heard: '…'".
- **Day safety:**
  - The title reads "Add to Wednesday's dinner" whenever the day isn't today.
  - "Yesterday" or "last night" in the text asks "Log this to yesterday? [Yes] [No, today]".
- **Simple Home:** a big "What did you eat?" button above a smaller ring. It opens the sheet on
  the meal for this hour.

## 5. The plan

Phases are ordered by how much of "doesn't work" they remove per hour. Each item is its own
commit unless marked. Sizes: S < half a day, M ≈ a day, L = multi-day.

### Phase 0 — stop the bleeding (bugs she hits)

| # | Item | Size | Fixes |
|---|---|---|---|
| 0.1 | Apollo error link: on a 401, refresh once and retry; log out only if the refresh fails. Refresh on `visibilitychange`. **Suite-wide `packages/api-client`, so it gets its own commit and a full api suite run.** | M | B1 |
| 0.2 | `/api/me` failure that isn't a 401 → keep the user and show "Can't reach FitnessGeek — retrying" | S | B2 |

### Phase 1 — UX quick wins (S each)

1. Kill "Nothing found / Try fewer words" when describe is available; hide "Create '<sentence>'"
   for sentences.
2. Replace the magnifier with a pencil, and add a new placeholder: "Tell me what you ate — e.g.
   two eggs and toast". Promote the first-run line here.
3. The describe row becomes a filled primary button with a spinner.
4. Rows get a visible **+ Add** pill and "cal".
5. Name the day in the add sheet title when it isn't today, and make "Same as yesterday's"
   name the actual day.
6. Simple Log: hide the calorie gear, the activity line and the FAB.
7. BP labels: "Top number (systolic)" / "Bottom number (diastolic)". Bigger portion buttons.
8. Today strip: "Weigh in" and "Add BP" open their quick-add directly (`?add=1`). Weight's FAB
   becomes "Log weight".
9. Don't run the deep or AI search under 3 characters.

### Phase 2 — medium

10. Sentence mode: fold the list away and skip the deep search for sentences. Multi-line box,
    `enterKeyHint`, big mic. (M)
11. A "Just added" strip on the meal card with Fix and Undo, which stays until her next action.
    (M)
12. EditLog: edit calories on describe-made entries, and move an entry to another day. (M)
13. Simple Home: a "What did you eat?" button above a smaller ring. (S)
14. Use the first-run goal: "Lose a little" offers the plan wizard in one sentence instead of
    "No daily target is set". (M)
15. Saved meals in suggest; "Log this" on My Meals. (M)

### Phase 3 — the composer (L, **one revertable commit**)

16. A `FoodComposer` that owns the empty, typing, thinking, result and error states, with the
    list as a child. Harness scenes for every state; clear the orphan PNGs.
17. Parse "yesterday", "last night" and weekday names server-side, with the confirm chip.
18. An offline queue for describe text, or the honest "can't log offline" (§6).

**Order I'd ship:** 0.4 and 0.10 today (small, and directly about Heather), then 0.1–0.3, then
the rest of Phase 0 with Phase 1 interleaved, then the composer.
